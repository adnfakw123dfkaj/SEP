# TradingAgents 启动提示词

## 1. 开工前先读什么

先读应用根目录的 [AGENTS.md](AGENTS.md)，再读本文件，随后读[架构文档](docs/architecture/architecture.md)。只查阅人工本次点名的需求在[需求表](docs/req/requirements.yaml)中的条目，以及 `docs/req/` 中同编号的短记录。

一次只做一条，按 **FR-03 → NFR-03 → FR-02 → NFR-02 → FR-01 → NFR-01** 实施。人工尚未点名时，先等指派。

## 2. 提交执行计划

写完含以下五项的计划后停止，等待人工批准。

1. **需求可追踪性**　列出需求编号、对应的架构接入点、拟修改的文件和该条在需求表中的测试名。
2. **接口契约**　指出本条涉及 AGENTS.md 第 6 节的哪些共享边界，说明怎样维持其他需求依赖的行为。
3. **范围边界**　列出允许修改的文件、明确不做的事项和冻结项。
4. **测试策略**　只使用本条在需求表中已有的测试名，采用离线替身、固定时钟，并说明每项怎样算失败。
5. **执行步骤**　按顺序列出本次实施和验证的步骤。

## 3. 等待人工批准后生成代码

只有人工批准计划后，才生成或修改代码。批准仅覆盖计划中的一条需求和列明的范围。

维持既定的主图和已确认口径。关键数据缺失统一失败，硬 `REVIEW` 只由 NFR-03 判定。重试次数保持未填，成本改善百分比和质量底线保持 `pending_baseline`。禁止引入 Token 截断、缩短辩论或早停。

## 4. 构建和自验证

只改获批计划中的文件，只运行计划列出的离线测试。验证结束后停下，报告修改过的文件、实际执行的测试命令及结果、当前需求是否通过和残留风险。等人工验收通过后，才开始下一条。

## 5. 人工检查点

- 提交计划后停止，等待人工批准。
- 测试完成并报告结果后停止，等待人工验收。
- 触及 AGENTS.md 第 8 节时立即停止，说明原因并询问人工。包括改动冻结口径，填写重试次数、成本改善百分比或质量底线，扩大修改范围，删除或改写已有测试，改动主图，记录密钥，以及新建其他治理文件。
